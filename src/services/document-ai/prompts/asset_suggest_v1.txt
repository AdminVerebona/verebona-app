## RÈGLES CRITIQUES — À RESPECTER IMPÉRATIVEMENT
════════════════════════════════════════════════════════════

**R1 — Zéro invention — RÈGLE ABSOLUE** : Ne suggère QUE ce qui est mot pour mot dans la section "Textes extraits des documents liés à ce bien" ci-dessus. N'utilise AUCUNE connaissance externe, AUCUNE déduction, AUCUNE inférence sur d'autres biens ou d'autres documents. Si une information n'est pas présente textuellement dans ces documents, omets le champ sans exception. Ne complète jamais un champ à partir de ta connaissance générale.

**R1a — ROUTAGE ACTIF PAR BIEN** : Les documents peuvent contenir des informations sur PLUSIEURS biens (ex: une facture listant plusieurs véhicules avec main-d'œuvre et pièces distinctes, ou un document groupé couvrant différents équipements). Tu dois IDENTIFIER ACTIVEMENT quelles données appartiennent au bien **{{ASSET_NAME}}** en utilisant les indices suivants :

- **Pour les véhicules** : marque, modèle (ex: "CUPRA LEON"), plaque d'immatriculation, numéro VIN, kilométrage associé à un véhicule spécifique
- **Pour l'immobilier** : adresse, nom du bien, numéro de lot, référence cadastrale
- **Pour les objets** : nom du produit, marque, numéro de série, référence article
- **Structure du document** : sous-totaux par article/ligne, tableaux, sections dédiées à un bien spécifique
- **Contexte** : le nom {{ASSET_NAME}} mentionné explicitement dans le document

⚠️ **RÈGLE ABSOLUE — NE PAS MÉLANGER** : Si un montant, une date, une valeur technique ou tout autre champ concerne clairement un AUTRE bien mentionné dans le même document, ne l'extrais PAS pour {{ASSET_NAME}}.
Si tu ne peux pas déterminer à quel bien rattacher une information avec suffisamment de certitude, omets-la plutôt que de risquer une contamination entre biens.

**R2 — Zéro valeur vide** : N'inclus un champ dans la réponse que si tu as une valeur concrète, non nulle et non vide.

**R3 — Zéro champ déjà renseigné** : Si un champ figure dans la liste "Champs déjà renseignés", ne le propose PAS. Exception : si la valeur existante est manifestement erronée (ex: "0", "null"), tu peux proposer une correction avec confidence "low".

**R4 — Calibration de la confiance** :
- "high" : valeur écrite noir sur blanc dans le document, sans ambiguïté.
- "medium" : valeur clairement déductible d'un contexte explicite.
- "low" : valeur probable mais interprétée — à éviter autant que possible. Si tu hésites, omets.

**R5 — Cohérence sémantique stricte** : Chaque champ a une définition précise (voir ci-dessous). Ne jamais mapper une valeur sur le mauvais champ même si elle semble "proche".

## DÉFINITIONS STRICTES DES CHAMPS — ANTI-CONFUSION
════════════════════════════════════════════════════════════

### Champ `description` (section `common`)
**Ce n'est PAS** une copie du texte brut du document.
**C'est** une description synthétique du BIEN lui-même, utile dans un Carnet d'Information du Logement (CIL).
Rédige 1 à 3 phrases courtes décrivant les caractéristiques du bien (type, surface, localisation, état général, éléments notables). Utilise uniquement des informations présentes dans les documents.
Ne mentionne pas le nom du fichier, ne copie pas de texte brut, n'écris pas de description de document.
Exemple acceptable : "Appartement de 68 m² situé au 3e étage, construit en 1978, chauffage collectif gaz, classe DPE D."

### Champ `acquisitionDate` (section `common`)
**Ce n'est PAS** : une date de DPE, une date de facture, une date d'assurance, une date de contrôle technique, une date de bail, une date quelconque dans un document.
**C'est UNIQUEMENT** : la date à laquelle le propriétaire actuel a acheté ou acquis le bien — visible dans un acte de vente notarié, un compromis de vente, ou un acte d'acquisition. Si le document n'est pas un acte d'achat/vente, n'extrais PAS cette date.

### Champ `acquisitionPrice` (section `common`)
**Ce n'est PAS** : le montant d'une facture de travaux, un loyer, une valeur estimée, des charges.
**C'est UNIQUEMENT** : le prix d'achat du bien mentionné dans un acte de vente ou compromis.

### Champ `charges` (section `occupancy_usage`)
**Ce n'est PAS** : un montant de facture, un coût de travaux, une prime d'assurance, un montant DPE.
**C'est UNIQUEMENT** : les charges de copropriété mensuelles ou trimestrielles du logement.

### Champ `occupancyStatus` (section `occupancy_usage`)
**Ce n'est PAS** : un statut d'occupation du logement (ex: "occupé").
**C'est** : le statut juridique de l'utilisateur vis-à-vis du bien. Valeurs autorisées uniquement :
- `PROPRIETAIRE` : si le document est un acte de vente, titre de propriété, ou indique explicitement que la personne est propriétaire.
- `LOCATAIRE` : si le document est un bail, contrat de location.
- `OCCUPANT_GRATUIT` : si le document indique une occupation à titre gratuit.
- `USUFRUITIER` : si le document mentionne un usufruit.
**RÈGLE ABSOLUE** : Ne suggère `occupancyStatus = PROPRIETAIRE` que si le document est clairement un acte d'achat/vente ou titre de propriété.

### Champ `occupancyNotes` (section `occupancy_usage`)
**C'est** : un texte libre résumant les informations d'occupation et d'usage du bien issues du document.
**RÈGLE ABSOLUE — COHÉRENCE AVEC `occupancyStatus`** : Le contenu des notes DOIT être cohérent avec le champ `occupancyStatus` (déjà renseigné ou extrait dans la même passe).
- Si `occupancyStatus` est `PROPRIETAIRE` (ou sera suggéré comme tel), les notes NE DOIVENT PAS mentionner "non propriétaire", "locataire", "occupation à titre gratuit" ou toute formulation contraire. Écris "occupant propriétaire" ou "propriétaire occupant".
- Si `occupancyStatus` est `LOCATAIRE`, les notes peuvent mentionner le bail, le loyer, le locataire.
- En cas de doute, omets le champ plutôt que de créer une incohérence.

### Champ `monthlyRent` (section `occupancy_usage`)
**Ce n'est PAS** : un montant quelconque dans un document.
**C'est UNIQUEMENT** : le loyer mensuel explicitement mentionné dans un bail ou contrat de location.
**RÈGLE ABSOLUE — COHÉRENCE** : Si `occupancyStatus` est déjà renseigné à `PROPRIETAIRE` (voir champs déjà renseignés), ou si le document indique que l'utilisateur est propriétaire (acte de vente, titre de propriété), NE SUGGÈRE JAMAIS `monthlyRent`. Un propriétaire ne paie pas de loyer.

### Champ `estimatedValueMode` (section `common`)
**Ce n'est PAS** : une description libre, une méthode quelconque, un texte du document.
**C'est** : le mode de valorisation utilisé pour établir la valeur estimée du bien. Valeurs autorisées uniquement :
- `ESTIMATION_AGENCE` : estimation réalisée par une agence immobilière.
- `EXPERTISE_NOTARIALE` : expertise réalisée par un notaire.
- `EXPERTISE_INDEPENDANTE` : expertise réalisée par un expert indépendant ou un commissaire-priseur.
- `AVIS_VALEUR` : avis de valeur (courrier/rapport d'agence sans engagement).
- `SIMULATION_OUTIL` : simulation via un outil en ligne (ex: Meilleurs Agents, SeLoger).
- `ESTIMATION_PERSONNELLE` : estimation personnelle du propriétaire.
**RÈGLE** : Si le document ne précise pas explicitement l'un de ces modes, n'extrais PAS ce champ.

### Champ `estimatedValue` (section `common`)
**Ce n'est PAS** : un prix d'achat, un loyer, un montant de facture, un coût de travaux.
**C'est UNIQUEMENT** : une valorisation estimée du bien par un professionnel ou une estimation explicite avec un chiffre précis.

### Champ `estimatedValueDate` (section `common`)
La date à laquelle l'estimation de valeur a été réalisée. Visible dans un rapport d'expertise, un avis de valeur, ou un courrier d'agence. Ce n'est pas la date d'achat ni la date du document.

### Champ `acquisitionLocation` (section `common`)
**Ce n'est PAS** : l'adresse du bien.
**C'est** : le lieu géographique de l'acquisition (ex: ville ou pays) si mentionné dans un acte d'achat.

### Champ `dpeClass` (section `performance_technical`)
La lettre unique (A à G) du classement énergétique DPE. Dans un texte DPE, elle apparaît souvent comme "Classe A", "Étiquette énergie : D", ou dans un tableau de classement. Prends la lettre qui correspond à la consommation d'énergie primaire, pas aux émissions CO₂.

### Champ `gesClass` (section `performance_technical`)
La lettre unique (A à G) du classement GES (gaz à effet de serre / émissions CO₂). Distincte du `dpeClass`.

### Champ `dpeDate` (section `performance_technical`)
La date de réalisation du DPE, visible dans le rapport DPE. Ce n'est pas la date d'expiration.

### Champ `estimatedValue` (sections `common` ou `valuation`)
**Ce n'est PAS** : un prix d'achat, un loyer, un montant de facture, un coût de travaux.
**C'est UNIQUEMENT** : une valorisation estimée du bien par un professionnel (expert, notaire) ou une estimation explicite.

### Champ `constructionYear` (section `physical_characteristics`)
L'année de construction du bâtiment. Un nombre à 4 chiffres (ex: 1978). Visible dans un DPE, un acte notarié, ou un permis de construire.

### Champ `livingArea` (section `physical_characteristics`)
La surface habitable en m², loi Carrez ou Boutin. Un nombre décimal ou entier, sans unité.

### Champ `registrationNumber` (section `vehicle_identification`)
La plaque d'immatriculation du véhicule. Format français : AA-123-BB.

### Champ `vehicleOwnershipStatus` (section `vehicle_usage`)
**C'est** : le statut juridique du détenteur vis-à-vis du véhicule. Valeurs autorisées uniquement :
- `PROPRIETAIRE` : si le document est une carte grise, un acte de vente, ou indique explicitement que la personne est propriétaire.
- `LLD` : si le document est un contrat de Location Longue Durée.
- `LOA` : si le document est un contrat de Location avec Option d'Achat (crédit-bail).
- `CREDIT` : si le document est un contrat de crédit auto (financement).
- `PRET_GRATUIT` : si le document indique un prêt ou utilisation à titre gratuit.
**RÈGLE COHÉRENCE** : Si `vehicleOwnershipStatus` est `LLD` ou `LOA`, ne suggère PAS `acquisitionPrice` ni `acquisitionDate` (on ne possède pas le véhicule, il n'y a pas de date ni de prix d'achat — mettre `null` / omettre ces champs).

### Champ `mileage` (section `vehicle_usage`)
**Ce n'est PAS** : la puissance, le PTAC, ou un autre nombre.
**C'est UNIQUEMENT** : le kilométrage/heures indiqué au compteur à une date précise.

### Champ `insuranceContractNumber` (section `vehicle_insurance`)
**C'est** : le numéro de contrat d'assurance, tel qu'imprimé sur le contrat, l'attestation ou l'avis d'échéance (ex: "62098322/2008"). Ce n'est pas le numéro de client.

### Champ `insuranceClientNumber` (section `vehicle_insurance`)
**C'est** : le numéro de client ou d'assuré chez l'assureur, distinct du numéro de contrat (ex: "1020754"). Souvent libellé "N° de client", "N° d'assuré" ou "Code client".

### Champ `insurancePremium` (section `vehicle_insurance`)
**C'est** : la prime/cotisation annuelle TTC de l'assurance, exprimée en nombre décimal (ex: 313.59). Ne pas inclure l'unité monétaire. Prendre de préférence la valeur la plus récente (avis d'échéance > contrat initial).
